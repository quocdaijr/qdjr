## Context

qdjr.dev today is a three.js playground: three "vibes" (cartoon / galaxy / terminal), a 3D hero on `/`, and a 17-stop scroll journey on `/about`. It is fun but it does not read as a CV. The owner is job-hunting and wants the site to open, by default, as a **plain, fast, professional CV**: enough information, no effects, nothing to wait for. The existing vibes stay, reachable through a small switcher.

Alongside, the site's profile content was checked against the owner's TopCV PDF (`~/Documents/QUOC-DAI-NGUYEN-TopCV.vn-020726.124725.pdf`, July 2026). The site copy (admin API, last edited 2026-10-12, identical to the bundled `app/data/profile.*.ts`) is newer and more detailed, but the CV holds four items the site lacks. They get merged in.

### Wayfinder map (charted this session; the way is now clear, so no `.scratch/` tickets are needed)

**Destination:** this plan, executed as three independently shippable PRs.

**Decisions so far** (made by the owner, 2026-11-08):
- *Pro home*: CV mode keeps the two-page split: a short intro on `/`, the full CV on `/about`.
- *Content*: **merge**. Add the CV's missing FireGroup bullets and `Python (FastAPI, Flask)` to the site; keep the site's extra detail; update both the admin API and the bundled fallback so they stay identical.
- *Years*: keep **"6+ years"** everywhere (the owner's call, despite 08/2018 → now being 8+).
- *Pro theme*: CV mode follows the OS `prefers-color-scheme`, not the Vietnam clock.
- *PDF*: a print stylesheet plus a "Print / Save as PDF" button on `/about`; no PDF file committed.

**Defaults settled by the planner (overridable):**
- Canonical term is **CV mode** (code value `cv`); the other is **Vibes mode** (`vibes`). UI labels: "CV" / "Vibes". The owner's words "professional", "resume" and "CV" all mean CV mode.
- Mode is remembered exactly like the vibe (localStorage + one-year cookie), default `cv` for every new visitor.
- In CV mode nothing from three.js loads, the three Google Fonts stylesheets are not requested (system font stack), no reveal animations, no frosted/backdrop-filter chrome. Trip pages (`/trips/[slug]`, `/trips/plan`) still draw their trip scene in both modes: it is the page's content, not decoration.
- The vibe switcher is hidden in CV mode; the chosen vibe is kept for when the visitor returns to Vibes mode.
- Blog and trips list pages in CV mode: same pages, paper background, no veil.

**Out of scope:** reworking the journey or scenes; a CV PDF file; the admin UI; `full_name`/`bio`/`tagline` API fields the site does not read; the address wording (CV and site both say Bình Định; left as is).

---

**Goal:** Ship a default, effect-free CV presentation of qdjr.dev with a small CV ⇄ Vibes switcher, and bring the profile content up to date with the owner's CV.

**Architecture:** The Pinia theme store gains a second persisted axis, `mode: 'cv' | 'vibes'`, mirrored to a `mode` cookie so SSR renders the right variant (same pipeline as the `vibe` cookie). `<html>` carries `data-mode`; in CV mode it carries **no** `data-vibe`, so every existing `[data-vibe=…]` rule and the vibe token blocks silently stop applying and a neutral `[data-mode="cv"]` token block (light + `prefers-color-scheme: dark`) takes over. The layout mounts `LazyVibeScene` only in Vibes mode or on trip pages. `/about` and `/` render a CV component or the existing journey/hero by `v-if` on the store.

**Tech Stack:** Nuxt 4.6 (SSR), Vue 3.5, Pinia, Tailwind v4 (CSS-first, `@custom-variant`), `@nuxtjs/i18n`, Vitest 5 (happy-dom), Playwright 1.64. Admin API: Go/Gin at `https://api.qdjr.dev/v1` (Bearer JWT).

**Spec:** the Context section above (decisions + defaults) is the spec; there is no separate document.

## Review Focus

1. **A visitor with a `vibe` cookie but no `mode` cookie** (every returning visitor on day one) must land in CV mode, not Vibes mode. Pinned in Task 4 (`initializeMode` ignores the vibe) and Task 11 e2e ("a saved vibe alone does not re-enable vibes").
2. **Trip pages in CV mode** must still render the trip scene and its controls, or the page is an empty panel. Pinned in Task 6 (`hasScene` unit test) and Task 11 e2e.
3. **Dark-OS visitor, first visit, SSR**: the server cannot know the scheme, so the CSS media rule must colour the page before hydration (no light flash) and the hydrated store must agree (no flip back to light). Pinned in Task 7 e2e with `page.emulateMedia({colorScheme: 'dark'})` and a check that `html` gets `.dark` after hydration.
4. **Switching to Vibes mode at runtime** must inject the font stylesheets and mount the scene without a reload. Pinned in Task 11 e2e ("the switcher enables vibes without a reload").
5. **The admin API content blob** is accepted by the site only if `content[locale]` has all seven sections (`pickProfileContent`); a partial PATCH would silently fall back to the bundled copy. Pinned in Task 3: the sync script PATCHes the whole `content` object and re-reads `/v1/profile` to verify equality.

- [ ] **Step 1: Create `scripts/sync-profile-content.ts`** (runs on Node 24 type-stripping; no tsx needed)

```ts
// Pushes app/data/profile.* to qdjr-admin so the API and the bundled fallback
// stay identical. Usage: ADMIN_EMAIL=… ADMIN_PASSWORD=… npm run profile:sync
import {PROFILE_CONTENT} from '../app/data/profile.ts'

const API_URL = (process.env.API_URL ?? 'https://api.qdjr.dev').replace(/\/+$/, '')
const {ADMIN_EMAIL, ADMIN_PASSWORD} = process.env
if (!ADMIN_EMAIL || !ADMIN_PASSWORD) {
  console.error('Set ADMIN_EMAIL and ADMIN_PASSWORD (a qdjr-admin user with profile:write).')
  process.exit(2)
}

interface Envelope<T> { data: T | null; error: {code: string; message: string} | null }

async function call<T>(path: string, init: RequestInit): Promise<T> {
  const res = await fetch(`${API_URL}${path}`, {...init, headers: {'content-type': 'application/json', ...(init.headers ?? {})}})
  const body = (await res.json()) as Envelope<T>
  if (!res.ok || body.error || body.data === null) throw new Error(`${init.method ?? 'GET'} ${path} → ${res.status} ${body.error?.code ?? ''} ${body.error?.message ?? ''}`)
  return body.data
}

const {access_token: token} = await call<{access_token: string}>('/v1/auth/login', {method: 'POST', body: JSON.stringify({email: ADMIN_EMAIL, password: ADMIN_PASSWORD})})
await call('/v1/admin/profile', {method: 'PATCH', headers: {authorization: `Bearer ${token}`}, body: JSON.stringify({content: PROFILE_CONTENT})})
const live = await call<{content: unknown}>('/v1/profile', {})
const same = JSON.stringify(live.content) === JSON.stringify(PROFILE_CONTENT)
console.log(same ? 'API profile content now matches app/data/profile.*' : 'WARNING: API content differs from the bundled copy after sync')
process.exit(same ? 0 : 1)
```

// Presentation mode: the plain CV (fast, no scene) or the three.js vibes.
export type Mode = 'cv' | 'vibes'
export const MODES: readonly Mode[] = ['cv', 'vibes'] as const
export const DEFAULT_MODE: Mode = 'vibes' // flipped to 'cv' in the cv-pages PR

      if (import.meta.client && !this.isInitialized) {
        const savedMode = localStorage.getItem(MODE_STORAGE_KEY)
        this.mode = isMode(savedMode) ? savedMode : this.mode
        persist(MODE_STORAGE_KEY, this.mode)
        const saved = localStorage.getItem(VIBE_STORAGE_KEY)
        this.vibe = isVibe(saved) ? saved : this.vibe
        persist(VIBE_STORAGE_KEY, this.vibe)
        this.isDarkMode = this.mode === 'cv' ? prefersDark : isNightInVietnam(now)

      this.mode = mode
      if (import.meta.client) persist(MODE_STORAGE_KEY, mode)
      this.applyTheme()

    syncClock(now: Date = new Date()) {

      if (this.mode !== 'cv') return

        html.classList.toggle('dark', this.isDarkMode)
        html.dataset.mode = this.mode
        if (this.mode === 'vibes') html.dataset.vibe = this.vibe
        else delete html.dataset.vibe

import {isMode, isVibe, MODE_STORAGE_KEY, useThemeStore, VIBE_STORAGE_KEY} from '~/stores/theme'
import {isNightInVietnam} from '~/utils/vnTime'

// Vibe fonts, vibes mode only. Three static stylesheets (one per vibe): the
// browser downloads binaries only for text it renders, so the inactive vibes
// cost one small CSS fetch each. CV mode uses the system stack and loads none.
const VIBE_FONT_LINKS = [
  {rel: 'stylesheet', href: 'https://fonts.googleapis.com/css2?family=JetBrains+Mono:wght@400;700&display=swap'},
  {rel: 'stylesheet', href: 'https://fonts.googleapis.com/css2?family=Fraunces:opsz,wght,SOFT,WONK@9..144,700,100,1&family=Bricolage+Grotesque:opsz,wght@12..96,400;12..96,600&display=swap'},
  {rel: 'stylesheet', href: 'https://fonts.googleapis.com/css2?family=Chakra+Petch:wght@600&family=Geist:wght@400;600&family=Geist+Mono:wght@400&display=swap'}
]
const SCHEME_QUERY = '(prefers-color-scheme: dark)'

// Theme bootstrap. A server render takes mode and vibe from their cookies (it
// cannot see localStorage); dark mode comes from the Vietnam clock in vibes
// mode and is left light in cv mode (tokens.css paints dark from the OS media
// query before any script runs). The client hydrates from Pinia's payload,
// restores the saved choices and keeps the clock / scheme in sync.
export default defineNuxtPlugin((nuxtApp) => {
  const themeStore = useThemeStore()
  if (import.meta.server && !import.meta.prerender) {
    const mode = useCookie(MODE_STORAGE_KEY)
    if (isMode(mode.value)) themeStore.mode = mode.value
    const vibe = useCookie(VIBE_STORAGE_KEY)
    if (isVibe(vibe.value)) themeStore.vibe = vibe.value
    themeStore.isDarkMode = themeStore.mode === 'vibes' && isNightInVietnam(new Date())
  }
  useHead({
    htmlAttrs: {
      'data-mode': () => themeStore.mode,
      'data-vibe': () => (themeStore.mode === 'vibes' ? themeStore.vibe : undefined),
      class: () => (themeStore.isDarkMode ? 'dark' : undefined)
    },
    link: () => (themeStore.mode === 'vibes' ? VIBE_FONT_LINKS : [])
  })
  if (import.meta.server) return
  nuxtApp.hook('app:suspense:resolve', () => {
    const scheme = window.matchMedia(SCHEME_QUERY)
    themeStore.initializeTheme(new Date(), scheme.matches)
    themeStore.startClock()
    scheme.addEventListener('change', (e) => themeStore.syncScheme(e.matches))
  })
})
